# Обновления FlightDeck через GitHub

Репозиторий — https://github.com/valerii-palch/FlightDeck.

## Первый запуск

1. Установи `FlightDeck-macOS-0.22.0.pkg` вручную один раз, если в твоей версии ещё нет кнопки **Настройки → Обновить приложение**. Кнопка доступна с версии 0.21.0.
2. Загрузи содержимое папки `GitHub` из архива в корень репозитория. Включи папку `.github/workflows` и файл `.gitignore`. На Mac скрытые файлы показывает `Cmd + Shift + .`. Если браузер не добавляет скрытую папку, создай файл через **Add file → Create new file**, имя `.github/workflows/release.yml`, и вставь текст из приложенного файла `release.yml`.
3. В репозитории открой **Settings → Secrets and variables → Actions → New repository secret**.
4. Добавь `FLIGHTDECK_UPDATE_PRIVATE_KEY`. Ключ уже создан на Mac в рабочей папке проекта, файл `.release-secrets/update-signing-key`. Скопировать его в буфер обмена можно командой ниже. Содержимое вставь в **Secret**, не в файлы репозитория.

   ```sh
   pbcopy < '/Users/admin/Documents/ChatGPT/Планировщик полетов/.release-secrets/update-signing-key'
   ```

5. В Supabase открой **Edge Functions → Secrets** и добавь `AVIATIONSTACK_KEY`. Через редактор **Edge Functions** разверни функцию `route-duration` с кодом из `supabase/functions/route-duration/index.ts`. Оставь проверку JWT включённой. Проверь расчёт в настольном приложении после входа в FlightDeck.
6. Открой **Actions → Release FlightDeck → Run workflow**. Укажи тег `v0.22.0`, нажми **Run workflow**.
7. Дождись завершения трех заданий. В **Releases** появятся установщики Mac и Windows, `macos-update.json`, файлы `latest*.yml` и контрольные данные Windows. Публикация происходит только после успешной сборки обеих платформ.

Если GitHub предлагает разрешить Actions в новом репозитории, разреши запуск workflow. Личный токен GitHub не нужен, публикация использует встроенный токен workflow.

## Следующая версия

Увеличиваем `CFBundleShortVersionString` и **обязательно** `CFBundleVersion` в `FlightDesk/Info.plist`; ту же пользовательскую версию ставим в `FlightDeck-Windows/package.json`. Например, `0.23.0` и сборка `27`. После загрузки изменений запускаем workflow с тегом `v0.23.0`. Уже опубликованный тег не используем повторно.

Пользователь нажимает **Обновить приложение**. Новая версия скачивается, проверяется и устанавливается; FlightDeck перезапускается. На Mac установку подтверждает системный запрос администратора. Отмена запроса оставляет приложение открытым и позволяет повторить попытку. Если версия уже актуальна, приложение сообщает об этом. Локальный журнал и облачный аккаунт находятся вне каталога приложения.

## Данные реальных рейсов

С версии 0.22.0 macOS и Windows получают оценку через Edge Function Supabase. Запрос требует действующего сеанса FlightDeck. Журнал по-прежнему даёт локальную оценку без входа в аккаунт. Ключ Aviationstack хранится в секретах Supabase. Установщики, автономный HTML и GitHub Actions его не используют.

## Подпись и файлы

macOS принимает только манифесты, подписанные ключом этого проекта, и проверяет SHA-256 пакета до запуска системного Installer. В приложение встроен только открытый ключ `tools/update-public-key.txt`. Закрытый ключ отсутствует в архиве и исходниках для GitHub. Сохрани его резервную копию в менеджере паролей; для уже установленных приложений нельзя просто заменить его новым ключом.

Windows использует `electron-updater` 6.8.10 и установщик NSIS. Данные обновления создаются electron-builder и загружаются из GitHub Releases. Проверяются контрольные суммы пакетов. Автоматическая установка при обычном закрытии выключена: обновление запускается кнопкой.

## Проверки перед распространением

На Mac собраны и проверены универсальное приложение Intel/Apple Silicon и установщик. Проверены подписи манифестов, повреждение данных, подмена ключа/URL и SHA-256. Проверены сценарии кнопки и Windows-обработчика с имитацией загрузки и ошибок. Реальная сборка Windows и сквозное обновление с одной опубликованной версии на другую проверяются после первого запуска Actions. В среде подготовки нет доступа к GitHub для публикации и нет интерактивного системного Installer для проверки запроса администратора.
